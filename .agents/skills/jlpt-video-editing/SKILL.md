# 按脚本剪辑教学视频

## 适用范围与目标

当用户要求剪辑当前项目的视频，例如“开启剪辑任务”“按脚本精剪视频”或“重剪视频”时，执行本流程并交付成片。适合口播、讲义录屏及中日文混合教学视频。用户本次明确要求优先于下列默认值。仅生成或修改逐字稿、整理语法资料、询问配置、解释文件或修改流程时，不自动剪辑视频。

项目根目录取当前工作目录或用户明确给出的路径，与本技能安装位置无关。调用示例：`$jlpt-video-editing 按最新脚本剪辑当前项目的视频`。

默认从 `original-videos/<level>/` 查找原始视频，并根据视频文件名到项目根目录的 `<level>/video-scripts/` 寻找对应脚本，依据脚本组织内容，保留原声与正常语速，删除重复表达、准备空白、重录、失败尝试和无效停顿，并完成音频降噪与响度统一。成片不添加字幕。完整表达优先，不以固定时长或压缩比例为目标。

## 输入与文件保护

- 原始视频按 JLPT 等级放在项目根目录的 `original-videos/<level>/`，例如 `original-videos/n3/`。视频格式例如 MOV、MP4、MKV、M4V；扩展名不区分大小写。排除成片、预览、缓存和 `editing/`、`output/` 中的文件。
- 以找到的视频为入口，从其所属等级确定脚本目录 `<level>/video-scripts/`，不跨等级匹配，也不再从 `original-videos/` 读取脚本或默认读取通用的 `script.txt`。脚本使用 UTF-8 文本文件。
- 根据视频去掉扩展名后的文件名查找对应脚本，优先匹配同名文件。视频用日文语法名、脚本用带等级前缀的罗马字命名时，核对同级语法文档的标题和脚本内容，确认唯一对应的语法点后配对，例如 `original-videos/n3/〜につれて.mov` → `n3/video-scripts/N3_nitsurete.txt`，`original-videos/n3/〜にとって.mov` → `n3/video-scripts/N3_nitotte.txt`。不得仅凭相似文件名猜测配对。
- 允许存在多个等级和多组素材；逐组独立剪辑并交付，不因放在同一文件夹而拼接。脚本库可以多于视频，未被视频选中的脚本不视为缺失输入。视频找不到对应脚本、存在多个候选或同一语法点有多个视频而关系不明时，记录并只询问必要的问题；配对明确的其他素材继续处理。
- 每次执行都重新读取最新脚本并保存其路径、修改时间和内容校验值；脚本更新后重新核对脚本与视频的对应关系及剪辑计划，不沿用旧脚本的取舍。
- 原视频和脚本不覆盖、不改写。成片放在 `output/`，中间文件放在 `editing/<任务名>/`；重复执行用新版本名，保留已有成片。
- 剪辑过程中产生的临时文件（分析音频、转写、关键帧、预览、缓存、日志等）统一放在 `editing/<任务名>/`，不纳入 Git 提交；`original-videos/` 文件夹及其全部内容也不纳入 Git 提交。通过 `.gitignore` 排除，保留本地文件。
- 路径以当前工作目录为基准，兼容中文、日文和空格。脚本使用 UTF-8；调用外部程序优先传参数数组，避免拼接未经转义的 shell 字符串。
- 以前任务的转写、剪辑点和缓存只供参考，必须核对源文件身份后才能复用。严禁把旧视频的时间点套到新视频。

## 画面与声音的硬性要求

- 每次先用 ffprobe 获取分辨率、SAR/DAR、旋转信息、时长、帧率/时间基、音轨与色彩信息，保存探测结果。
- 保持原始分辨率、长宽比、画面方向和全部画面内容。禁止为了套模板而缩放、裁切、拉伸或加黑边，禁止默认改成 1080×1920。
- 遇到旋转元数据或非方形像素，先核对实际显示方向及比例，再制定编码方案；避免重复旋转或强制 SAR=1 导致变形。发现无法同时满足要求时说明具体冲突。
- 保留原声、音调、语速和可用声道，进行适度降噪与响度统一。不默认加速、配音、背景音乐或转场特效；降噪不能以损伤人声为代价。
- 不新增烧录字幕、软字幕轨或 SRT/ASS 交付文件。转写仅供内部对齐和剪辑使用。原画面中的讲义文字或已有硬字幕保留，不裁切、遮盖或擦除；导出时只映射选定的视频与处理后的音频，不带入可选字幕轨。
- 转写用的单声道 16 kHz 音频仅供分析；最终音轨来自原视频，不使用低采样率分析音轨替代。
- 优先保持原帧率。可变帧率录屏确有剪辑同步需要时可转为 30 fps 恒定帧率；不得改变播放速度，并在交付说明中注明。其他帧率按素材决定。

## 环境适配

先探测现有工具，不假定操作系统、Python 路径、显卡或已有模型：

- 必需：FFmpeg、ffprobe；检查 `silencedetect`、`loudnorm` 和可用降噪滤镜（例如 `afftdn`）。不要求字幕滤镜或额外字体。
- 建议：Python 3、faster-whisper 或其他可用的本地带时间戳语音识别工具。需要 Python 包时优先项目虚拟环境，不改动全局环境。
- 使用已有模型；按机器性能和识别质量选择多语言模型。小模型可用于初步定位，不能直接信任其日语转写。
- 缺依赖时在当前权限允许范围内安装或使用等效工具。下载模型需要网络；离线时检查本地缓存。遇到真实阻碍说明缺什么及解决方法，不声称已完成不可执行的步骤。
- 硬件编码先做小样测试，失败则使用软件 libx264，无须为编码器选择单独等待用户决定。

## 执行流程

### 1. 分析素材

读取脚本全文，理解开头、知识点、例句、解释和总结的顺序。抽取视频接触表及必要的关键帧，确认画面变化、翻页和标注与讲话的对应关系。

提取分析音频，生成带句级或词级时间戳的转写，保存原始转写。中日文混合内容应结合脚本校对，必要时对不确定片段重新识别或试听。仅凭识别结果的重复，不能认定原音频发生了重录。

### 2. 按脚本选择内容

- 为脚本段落建立“脚本文本 → 原视频时间段”的对应关系。
- 同一语句、词语或片段出现重复阅读或重录时，以原视频时间线靠后的读音为准：保留最后一次对应阅读，删除此前的重复。不得因前一次更流畅、画面更稳定或转写更接近脚本而改选前一次。
- 最后一次只重读词语或半句时，用该次读音替换此前对应部分，保留前后未被重读的内容。最后一次不完整时，不伪造缺失内容；记录确实无法接续的问题，不擅自回退到此前读音。
- 删除口误后的废弃尝试、重复词句、重说的半句、无意义语气词、无关插话，以及不在脚本中的独立例句。
- 同一观点即使换了措辞，只要没有增加信息，也按重复表达处理，保留时间线靠后的表达。检查相邻句和跨段落重复，不局限于逐字匹配。
- 日语例句与中文翻译、举例后的语法分析以及承担归纳作用的简短总结不是同义赘述，应保留；有新信息的简短补充可保留。
- 保留完整的例句、翻译、语法解释和总结，不为追求短而误删教学内容。
- 结尾的「見てくれてありがとう」必须完整保留，即使脚本未写明，也不得作为无关插话、重复表达或片尾空白删除；如有多次录制，按时间线靠后优先的规则处理，保留前后未被重读的内容以确保结尾完整。
- 脚本用于校正内部转写的识别错字和术语，剪辑仍须忠实于实际讲话；重复阅读的选段遵循时间线靠后优先的规则。不能用修改转写来掩盖音频里的错误，也不能补出原音频没有说的整段内容。
- 发现脚本内容未录制、重录都不完整或意思实质不一致时，记录具体缺失/冲突并说明，不自行伪造讲话。

### 3. 删除停顿与衔接剪辑点

主动清理片头片尾空白、句间等待、句中犹豫、停下来思考或重读的部分，以及翻页和操作时无讲解、无必要视觉信息的等待。目标是紧凑连贯，不只处理超过一秒的长静音。

以下参数为候选检测起点，依据实际噪声底和说话节奏调整：

| 项目 | 默认值 |
| --- | --- |
| 静音检测阈值 | -35 dB，结合噪声底调整 |
| 检测最短静音 | 0.25 秒 |
| 无效停顿的处理 | 删除中间空白，仅保留语音边界保护 |
| 前一句结束后的保护 | 约 0.08～0.12 秒 |
| 后一句开始前的保护 | 约 0.05～0.08 秒 |
| 切口音频淡入/淡出 | 必要时约 5～10 毫秒，位于非语音边缘 |

静音检测只提供候选点，须结合语音活动检测、波形、转写和画面确认。噪声较大时可以对分析副本先做轻度降噪辅助定位，但不得改变时间轴。对不足 0.25 秒的犹豫或重复也可按语义剪除，不机械删除所有低电平区间。

避免切掉辅音、日语长音、促音、句尾或下一句开头。只保留支持断句、必要呼吸及理解画面所需的最短间隔；涉及关键翻页、画笔标注或示范动作时，保留动作本身，删除前后的空等。不得把词内停顿当作多余空白，也不通过全片加速替代剪辑。

视频与音频必须使用同一套保留区间和输出时间映射。逐段重置时间戳并正确拼接，或使用经过检查的统一时间线。不要对音频和视频分别自动删静音。切口淡入淡出不得改变片段时长；如使用交叉淡化，必须同步修正画面与总时间轴，避免累计错位。

保存机器可读剪辑计划，至少包含源文件、保留区间、删除原因（重复/停顿/口误等）、源时间到成片时间的映射及未解决问题。时间单位统一为秒，明确区分原视频时间与成片时间。

### 4. 音频降噪与响度统一

处理顺序：评估原声及噪声 → 适度降噪 → 按统一时间线剪辑并修整切口 → 必要的段间增益调整 → 全片响度测量与统一 → 最终编码及复测。

**降噪：**

- 检查底噪、风扇声、低频轰鸣、电流声和口齿清晰度；在有代表性的讲话段与静音段做处理前后对比。
- 优先使用本地可用降噪工具。稳定底噪可从 `afftdn` 约 6～10 dB 的温和降噪量开始，依据噪声样本调整；无纯噪声区间时不要拿讲话做噪声样本。
- 仅检测到相应问题时才加低切或窄带陷波，不默认削弱人声低频，也不采用会截断轻声、词尾的强噪声门。
- 不追求绝对静音。出现水声、金属声、抽吸、齿音破碎或明显闷声时降低处理强度。源音频已经干净时允许零降噪增益，并记录判断依据。
- 保留采样率、声道和时间长度；补偿可能产生的处理延迟，不使用低采样率转写音频作为最终声音。

**响度：**

| 项目 | 默认目标 |
| --- | --- |
| 综合响度 | -16 LUFS |
| 真峰值上限 | -1.5 dBTP |
| loudnorm 的 LRA 参数 | 7 LU，作为动态控制参数，不要求成片恰好达到此值 |
| 综合响度验收参考 | 距目标约 ±1 LU；无法兼顾音质时说明实际值与原因 |

- 不同录制段落音量明显跳变时先做温和的段间增益匹配，再处理全片；不要逐词或逐个短切片单独归一化，避免音量抽动和底噪忽大忽小。
- 在最终剪辑、降噪和增益调整后的完整音轨上，优先进行 `loudnorm` 两遍处理：第一遍保存 JSON 测量结果；第二遍使用同一上游处理链和真实测量值。剪辑或降噪参数变化后必须重新测量。
- 若使用线性模式，要确认测量条件允许；无法同时满足响度与真峰值目标时可使用动态模式，避免过度压缩。不得只改峰值音量就声称完成综合响度统一。
- 显式设置最终采样率，避免 loudnorm 内部过采样导致意外更改输出采样率。静音或极短音轨的无效测量值应单独处理，不将无穷值套入第二遍。
- 对编码后的成片音轨重新测量 LUFS、真峰值及 LRA，检查 AAC 编码后的峰值变化；若超限，调整余量并重新输出。保存处理前后指标和所用参数。

### 5. 导出

一般 SDR、偶数尺寸视频的默认交付设置：MP4、H.264/libx264、CRF 18、preset veryfast、AAC 192 kbps、faststart。保留源采样率和声道，必要时根据源质量调整。

像素格式优先兼容的 yuv420p，但不得为满足编码限制悄悄改尺寸。奇数尺寸、HDR、10 bit、特殊色域或非方形像素素材应先选择能满足保真要求的方案，明确任何不可避免的兼容性取舍。正确处理色彩范围及标签，避免发灰或过曝。

不要照抄旧项目中的 `44100 Hz / 1470 samples` 音频分块参数：它只对应 30 fps 的特定情况。任何帧级选段方案都必须根据实际帧率和采样率计算，处理浮点边界，防止累计音画漂移。

先导出包含正常讲话、底噪和剪接点的短预览，检查画面及处理后的声音，再导出完整成片。全片响度不能用短预览的测量值代替。最终文件完成后再做完整验证。

### 6. 验证与交付

- 比较输入输出的分辨率、显示比例、像素比例及方向，确认无裁切和变形。
- 完整解码成片，检查损坏、异常黑帧和意外静音；抽查开头、重录剪接点、每条例句和结尾。
- 检查时间线总时长与成片一致，音视频起止相符。允许编码帧/音频包造成的小偏差，但不能有可感知的累计漂移；必要时与源音频片段做相关性验证。
- 检查无新增字幕、无附带字幕轨，脚本所需内容没有误删，重复表达和无效停顿已清理；尤其复核剪口是否吞字、爆音、衔接突兀或画面跳到错误页面。
- 逐组复核重复阅读的选段：保留最后一次对应读音，并在剪辑计划中记录被替换的较早片段；局部重读不得误删前后未被重读的内容。
- 确认结尾完整保留「見てくれてありがとう」，没有截断或误删。
- 复测最终音轨响度和真峰值，抽查各段音量是否一致，以及降噪是否保留清晰、自然的人声。保存实测值；未达到目标时说明具体原因，不只报告配置目标。
- 如实区分已完成的探测、解码、看图、试听和自动对齐检查；没有试听或没有能力检查的项目不能声称通过。
- 最终交付 `<主题或源文件名>_精剪版.mp4` 和简短剪辑说明，不交付字幕文件。说明原/成片时长、分辨率、重复表达与停顿的清理情况、降噪方式、最终实测响度/真峰值、帧率变化及实际问题。
- 对话回复简短，给出成片链接。无需用户逐步确认常规剪辑选择，执行到导出和检查完成；遇到缺失输入或无法解决的实质冲突再提问。

## 可迁移性

本技能随项目存放在 `.agents/skills/jlpt-video-editing/`，不依赖原始电脑、之前的聊天或 `editing/` 中的旧脚本。换电脑时保留项目中的完整技能目录，将视频放入项目的 `original-videos/<level>/`，将对应脚本放入同级的 `<level>/video-scripts/`；日文视频名与罗马字脚本名不同的，保留用于核对的同级语法文档。在 Codex 中打开项目工作文件夹，并使用 `$jlpt-video-editing` 或直接要求剪辑视频。工具、模型和音频滤镜须在新电脑上重新探测。
